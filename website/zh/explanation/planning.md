# 规划阶段 {#planning-stages}

引擎先确定视口，并解析一棵布局树。
它在加载内容前校验内容项名称和选项。
随后为每个已选内容项实例准备内容，并规划完整树结构。
渲染器根据成功的方案创建Scriptable原生视图。

## 保留内容与分组边界 {#content-and-boundaries}

成功方案包含每个已选内容项实例。
这包括重复名称，以及可见的空状态和错误状态。
引擎不会为了容纳内容而删除字段或条目。
内容项原有的行数限制仍然有效。

`auto`自动布局可以调整直接子节点顺序。
`flow`保序布局会保持逐行阅读时的列出顺序。
手动分组在这两种自动容器内都会保持完整。
内容项不能移出该分组。

## 先尝试预设 {#presets}

在每个字号阶段，自动区域先尝试当前尺寸类别对应的预设结构。
预设包括行、列、网格、横向通栏和侧边分组。

| 尺寸类别 | 优先尝试的预设方向 |
| --- | --- |
| `small` | 侧边分组 |
| `medium` | 水平分组 |
| `large` | 垂直分带 |

预设使用测得的内容需求和分配宽度。
它们不指定固定像素坐标。
如果预设无法容纳内容，引擎会进一步搜索顺序和分组。

## 使用有下限的字号回退 {#font-fallback}

引擎按以下顺序尝试：

1. 以配置字号的100%尝试预设和搜索。
2. 以90%字号尝试预设和搜索。
3. 以80%字号尝试预设和搜索。
4. 以70%字号尝试预设和搜索。

第一个成功阶段即为最终选择。
原始字号方案优先于较小字号方案。
只有自动区域内的内容项可以进行字体适配。
同级手动内容保留原始字号。

原始字号至少为10pt的文本不会缩小到10pt以下。
原始字号小于10pt的文本保持原始大小。
已保存的字体偏好不会改变。
内边距、间距、尺寸和显式变体仍然作为约束。
测量和渲染使用相同的选定快照。

内置内容项支持这种适配。
自定义内容项若要支持字体适配，需要实现可选的[`atFontScale`契约](../reference/custom-items.md#font-adaptation)。
没有该方法时，自定义内容项保留原始字体设置。

## 共享可用空间 {#share-available-space}

多个自动区域可以共享手动父节点的可用空间。
正数`grow`权重会在满足最低需求后分配剩余空间。
因此，权重为1和2并不保证最终尺寸比例恰好为1:2。
参见[属性](../reference/syntax.md#properties)。

## 遵守规划限制 {#limits}

| 限制 | 默认值 |
| --- | --- |
| 每个已解析布局的节点数 | 128 |
| 嵌套层数 | 12 |
| 每个自动区域的直接子节点数 | 12 |
| 每个自动区域的结构候选数 | 256 |
| 每个布局方案的不同测量次数 | 4,096 |
| 每个中间候选前沿保留的组合数 | 24 |

候选预算涵盖不同宽度、预设与搜索阶段，以及字号缩放阶段。
阶段配额会为后续阶段预留尝试次数。
测量缓存复用内容项、宽度、变体和缩放比例都不变的结果。
相同快照和配置会产生相同搜索行为。
引擎不会穷举所有可能排列。

硬性预算耗尽可能产生`SEARCH_LIMIT_REACHED`。
有限的候选前沿或阶段剪枝可能在完整方案中产生`SEARCH_TRUNCATED`。
字号缩小会在完整方案中产生`FONT_ADAPTED`。

成功的纯规划器结果包含`strategy`和`fontScale`。
`strategy`为`manual`、`presets`或`search`。
这些结果描述规划行为，不代表真机验证。
请为每个目标配置完成[真机检查](../guide/device-checks.md)。
